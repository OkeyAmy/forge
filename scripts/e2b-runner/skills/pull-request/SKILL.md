# Pull Request Skill

Use this after implementation and validation.

## Responsibility

Prepare a maintainer-friendly branch or pull request.

## Process

1. Push only when there are real changes.
2. Use a branch tied to the issue, such as `forge/issue-123`.
3. Include changed files, checks run, check results, and known risks.
4. Link the PR to the issue.
5. Keep the PR title short and specific.

## Output

- Branch name.
- Compare URL.
- Pull request URL when created.
- Changed files.
- Verification summary.

## Failure Handling

If PR creation fails but the branch pushed, report the compare URL and the PR
creation error.
